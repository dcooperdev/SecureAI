*   **Conexiones Externas (C2)**:
    La telemetría de `sensor_procesos` no reporta conexiones externas en estado `ESTABLISHED`. Todos los puertos listados se encuentran en estado `LISTEN` con `remote_ip: null`, indicando que están a la espera de conexiones entrantes, pero no hay sesiones activas salientes o persistentes detectadas en este conjunto de datos que sugieran actividad de Comando y Control (C2).

*   **Vulnerabilidades (CVE Lookup)**:
    Los puertos abiertos detectados en `PC-DAVID` (Windows 10.0.19045) representan una superficie de ataque significativa y están asociados a CVEs conocidos y riesgos elevados:
    *   **Puerto 445 (SMB - Server Message Block)**: **RIESGO ALTO**. Este puerto es un vector principal para ataques de ransomware (ej. WannaCry, NotPetya), explotación de vulnerabilidades como EternalBlue (CVE-2017-0144 al CVE-2017-0148), movimientos laterales no autorizados y ataques de fuerza bruta/robo de credenciales. Aunque el OS esté parcheado, una configuración laxa o un usuario comprometido pueden habilitar su abuso.
    *   **Puerto 5432 (PostgreSQL)**: **RIESGO ALTO**. La exposición directa de una base de datos PostgreSQL a la red (especialmente si es pública o de fácil acceso desde la LAN) es crítica. Representa un alto riesgo de inyección SQL, exfiltración de datos, elevación de privilegios y ejecución remota de código si la instancia de PostgreSQL no está debidamente configurada, parcheada o protegida con autenticación robusta.
    *   **Puerto 445 y 139 (SMB y NetBIOS)**: **RIESGO ALTO**. La combinación de SMB y NetBIOS es una debilidad conocida. El puerto 139, en particular, es una implementación de SMB más antigua que generalmente se desactiva por seguridad. Su presencia sugiere la posibilidad de configuraciones heredadas vulnerables.
    *   **Puerto 135 (RPC - Remote Procedure Call)**: **RIESGO MEDIO**. Aunque es un componente central de Windows y se considera menos directamente explotable que SMB, ha sido históricamente objetivo de vulnerabilidades (ej. a través de servicios que dependen de RPC como Print Spooler, aunque no directamente asociados a este puerto en la telemetría). Su exposición aumenta la superficie de ataque del sistema.

### 4. Advertencia Crítica

**¡ADVERTENCIA CRÍTICA: RIESGO ELEVADO DE RANSOMWARE Y COMPROMISO DE DATOS!**

La exposición de los puertos **445 (SMB)** y **5432 (PostgreSQL)** directamente en el host `PC-DAVID` es una vulnerabilidad de severidad **ALTA**. El protocolo SMB (445 y 139) es el principal vector de entrada para ataques de ransomware y para movimientos laterales dentro de la red. El puerto 5432, al exponer una base de datos PostgreSQL, es un objetivo prioritario para la exfiltración de datos y la manipulación de información crítica. Este escenario configura un riesgo inminente para la integridad y confidencialidad de los activos de la organización.

### 5. ACCIONES DE 5 MINUTOS (Quick Wins)

Para mitigar inmediatamente la exposición crítica detectada, ejecute los siguientes comandos de PowerShell con privilegios de administrador. Estas acciones bloquearán el acceso entrante a los puertos vulnerables.

```powershell
# Bloquear puerto 445 (SMB) - CRÍTICO para prevenir ransomware
New-NetFirewallRule -DisplayName "GALT_AI_Block_SMB_445_Inbound" -Direction Inbound -LocalPort 445 -Protocol TCP -Action Block -Description "Bloqueo de puerto 445 (SMB) por alto riesgo de seguridad."

# Bloquear puerto 139 (NetBIOS) - CRÍTICO para prevenir ataques SMB heredados
New-NetFirewallRule -DisplayName "GALT_AI_Block_NetBIOS_139_Inbound" -Direction Inbound -LocalPort 139 -Protocol TCP -Action Block -Description "Bloqueo de puerto 139 (NetBIOS) por alto riesgo de seguridad."

# Bloquear puerto 5432 (PostgreSQL) - CRÍTICO para proteger la base de datos
New-NetFirewallRule -DisplayName "GALT_AI_Block_PostgreSQL_5432_Inbound" -Direction Inbound -LocalPort 5432 -Protocol TCP -Action Block -Description "Bloqueo de puerto 5432 (PostgreSQL) por alto riesgo de seguridad."

# Bloquear puerto 135 (RPC) - Reduce la superficie de ataque de Windows RPC
New-NetFirewallRule -DisplayName "GALT_AI_Block_RPC_135_Inbound" -Direction Inbound -LocalPort 135 -Protocol TCP -Action Block -Description "Bloqueo de puerto 135 (RPC) para reducir la superficie de ataque."

# (Opcional) Deshabilitar el servicio de Servidor SMB si no es estrictamente necesario:
```

### 6. Plan de Acción Técnico (Largo Plazo)

Estas acciones son esenciales para establecer una postura de seguridad robusta y sostenible, abordando las causas raíz de las vulnerabilidades detectadas:

1.  **Revisión de Necesidad de Servicios Expuestos**: Evaluar si los servicios SMB (445, 139) y PostgreSQL (5432) necesitan estar accesibles desde la red en este equipo. En muchos entornos, la base de datos PostgreSQL debe ser accesible solo localmente o desde un segmento de red muy restringido. SMB debería ser reemplazado por soluciones más seguras o, si es indispensable, configurarse con restricciones de IP y autenticación fuerte.
2.  **Parcheo y Actualización de Software**: Asegurar que el sistema operativo Windows 10.0.19045 y la instancia de PostgreSQL estén actualizados con los últimos parches de seguridad. Las vulnerabilidades de SMB, aunque antiguas, persisten en sistemas sin parches.
3.  **Configuración Segura de PostgreSQL**:
    *   Implementar autenticación robusta (ej. certificados SSL/TLS, autenticación SCRAM-SHA-256).
    *   Restringir el acceso a la base de datos a IPs autorizadas mediante `pg_hba.conf`.
    *   Aplicar el principio de mínimo privilegio a las cuentas de usuario de la base de datos.
    *   Monitorear los logs de acceso de PostgreSQL para detectar intentos de intrusión.
4.  **Segmentación de Red**: Implementar reglas de firewall a nivel de red (en el router o firewall perimetral) para segmentar el tráfico, aislando el equipo `PC-DAVID` o las bases de datos en un segmento de red independiente con acceso estrictamente controlado.
5.  **Hardening del Sistema Operativo**: Aplicar un "baseline" de seguridad para Windows 10, deshabilitando servicios innecesarios, fortaleciendo la configuración del firewall de Windows y aplicando políticas de seguridad de grupo.
6.  **Principio de Mínimo Privilegio (PoLP)**: Asegurar que los procesos y servicios críticos (ej. PostgreSQL) se ejecuten con los privilegios mínimos necesarios para su funcionamiento.
7.  **Monitorización Continuada**: Implementar herramientas de monitoreo de red y EDR (Endpoint Detection and Response) para detectar patrones de ataque, escaneos de puertos y actividad inusual en tiempo real.
