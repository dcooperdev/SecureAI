### 6. **ACCIONES DE 5 MINUTOS (Quick Wins)**

Para mitigar el riesgo de forma inmediata, ejecute los siguientes comandos en una terminal de PowerShell con privilegios de administrador. Estas acciones bloquearán el acceso externo a los servicios más críticos.

```powershell
# Bloquear el puerto 445 (SMB) para conexiones entrantes.
# Esto previene el acceso externo a recursos compartidos y ataques basados en SMB.
New-NetFirewallRule -DisplayName "Block SMB Inbound" -Direction Inbound -LocalPort 445 -Protocol TCP -Action Block -Force
Write-Host "Regla para bloquear puerto 445 (SMB) creada."

# Bloquear el puerto 5432 (PostgreSQL) para conexiones entrantes.
# Esto previene el acceso externo directo a la base de datos PostgreSQL.
New-NetFirewallRule -DisplayName "Block PostgreSQL Inbound" -Direction Inbound -LocalPort 5432 -Protocol TCP -Action Block -Force
Write-Host "Regla para bloquear puerto 5432 (PostgreSQL) creada."

# Deshabilitar NetBIOS sobre TCP/IP si no es estrictamente necesario para la operatividad.
# Esto ayuda a mitigar la exposición del puerto 139.
# Esta acción requiere reiniciar la interfaz de red o el sistema.
# Get-NetAdapter | ForEach-Object { Set-NetAdapterAdvancedProperty -Name $_.Name -DisplayName "NetBIOS Settings" -DisplayValue "Disable NetBIOS over TCP/IP" }

# Si la funcionalidad SMB es requerida para uso interno (ej. compartir archivos con otros PCs de confianza),
# considere restringir la regla a IPs específicas en lugar de un bloqueo total o segmentar la red.
```

### 7. **Plan de Acción Técnico (Largo Plazo)**

Estas son las directrices para una postura de seguridad sostenible:

1.  **Revisión y Justificación de Servicios:** Identifique la necesidad real de los servicios que exponen puertos críticos (SMB, PostgreSQL). Si no son esenciales, deshabilítelos o desinstálelos.
2.  **Parcheo Continuo:** Asegure que el sistema operativo (Windows 10.0.19045) y todas las aplicaciones (incluido PostgreSQL) estén actualizados con los últimos parches de seguridad. Implemente un ciclo de gestión de parches.
3.  **Endurecimiento de Servicios:**
    *   **SMB:** Deshabilite SMBv1. Restrinja SMBv2/v3 a redes de confianza mediante firewalls y autenticación robusta. Considere el uso de SMB Encryption y SMB Signing.
    *   **PostgreSQL:** Configure la autenticación robusta (ej., contraseñas complejas, autenticación de certificado). Restrinja el acceso a la base de datos solo a las IP o rangos de red que realmente lo necesiten. Utilice SSL para cifrar el tráfico de la base de datos.
4.  **Segmentación de Red:** Isole los sistemas que ejecutan servicios críticos en segmentos de red dedicados (VLANs), limitando la comunicación solo a lo estrictamente necesario.
5.  **Principios de Mínimo Privilegio:** Asegure que los procesos se ejecuten con los mínimos privilegios necesarios y que los usuarios solo tengan acceso a los recursos indispensables.
6.  **Monitorización Avanzada:** Implemente herramientas de detección y respuesta de endpoints (EDR) y monitorización de red para detectar actividades anómalas en puertos y servicios críticos, así como intentos de explotación.
7.  **Auditoría de Configuración:** Realice auditorías periódicas de la configuración de seguridad del sistema y de las aplicaciones para asegurar el cumplimiento de las políticas de seguridad.
8.  **Formación de Concienciación:** Eduque a los usuarios sobre las mejores prácticas de seguridad, especialmente en el manejo de datos y el acceso a la red.

Su falta de acción frente a estos riesgos no es una opción viable en el entorno actual de amenazas. Recomiendo implementar estas acciones con la máxima prioridad.
