## 7. Plan de Acción Técnico (Largo Plazo)

1.  **Parcheo y Actualización Continua**: Asegure que Windows 10.0.19045 esté siempre actualizado con los últimos parches de seguridad de Microsoft para mitigar vulnerabilidades conocidas en SMB, RPC y otros servicios del sistema operativo.
2.  **Principio de Mínimo Privilegio**: Revise los permisos y las cuentas bajo las cuales se ejecutan servicios como PostgreSQL. Evite que servicios de terceros se ejecuten con privilegios elevados (`SYSTEM/Protected`) si no es estrictamente necesario.
3.  **Segmentación de Red**: Implemente una segmentación de red estricta. Los puertos críticos (445, 139, 5432, 135) no deberían ser accesibles desde redes no confiables (ej. Internet) ni desde segmentos internos que no los requieran. Utilice firewalls de capa de aplicación para inspección profunda.
4.  **Hardening de Servicios**:
    *   **SMB**: Deshabilite SMBv1 si aún está activo. Configure SMB para requerir SMBv2/v3 y firmar/cifrar comunicaciones. Restrinja el acceso a recursos compartidos SMB a usuarios y grupos específicos.
    *   **PostgreSQL**: Asegure que PostgreSQL solo escuche en la interfaz de red necesaria (preferiblemente localhost o una IP interna específica). Implemente autenticación fuerte, cifrado en tránsito (SSL/TLS) y auditoría de accesos. Revise y fortalezca la configuración `pg_hba.conf`.
5.  **Monitoreo Activo (EDR/XDR)**: Despliegue y mantenga soluciones de Detección y Respuesta de Endpoint (EDR) o Detección y Respuesta Extendida (XDR) para monitorear procesos, conexiones de red y comportamientos anómalos en tiempo real, lo que permitiría una detección proactiva de C2 o movimientos laterales.
6.  **Revisión de Logs y 'AccessDenied'**: Investigue el origen de los permisos 'AccessDenied' para las rutas de ejecutables de procesos críticos. Asegure que la telemetría capture las rutas completas y que los logs sean accesibles para análisis forense.
